# 单人仓库管理系统（Termux 版）

从原《仓库进出管理.xlsm》提取结构改造而成：保留"物料行 × 每日进/出 × 汇总 × 预警"的布局思路，
改为**单据流水驱动**，库存自动计算，不再有原表 `#REF!` 损坏、公式不覆盖新行的问题。

## 一、安装（Termux 一次搞定）

```bash
pkg update && pkg install python
cd ~/storage/downloads/warehouse   # 或你解压到的任意目录
chmod +x run.sh
./run.sh
```

首次运行会自动装 Flask、建数据库 `warehouse.db`，并导入原表 32 种物料档案。
看到提示后，用手机浏览器打开 **http://127.0.0.1:8080**。

> 想换端口：`PORT=9000 ./run.sh`
> 想把数据库放别处：`WAREHOUSE_DB=/sdcard/wh.db ./run.sh`

## 二、五个页面（底部导航栏切换）

| 页面 | 用途 |
|---|---|
| 首页 | 今日/本月进出合计、库存预警清单、最近单据 |
| 台账 | 点物料行的 📈 看该物料逐笔进出与滚动结存 |
| **入库** | 📥 只做入库，A-G 七列齐全的表格，一次填多行 |
| **出库** | 📤 只做出库，带可用库存提示、超库存自动拦截 |
| 流水 | 全部单据；也可从入库/出库页进各自的流水 |
| 库存 | 实时库存 = 期初 + 入库 − 出库，可只看预警/零负 |
| 月报 | 复刻原模板：物料 × 每日进/出 × 汇总 × 月末结存 |
| 物料 | 档案增删改查，设置期初结存与安全库存（预警值） |

### 修改物料：两种方式，A–G 列全部可改

**① 表格编辑（推荐，改得多时用）**
「物料」页点 **✎ 表格编辑 A-G**，整张表变成可编辑网格，
物料名称 / 料号 / 类型 / 规格 / 宽幅 / 供应商 / 单位 / 状态 / 期初 / 安全库存
每一格都能直接改，横向滑动看后面的列，改完点 **保存全部修改**。

**② 勾选批量改（改某一列的规律内容时用）**
勾选物料（可全选）→ 选要改的列 → 执行。可选列：
**物料名称、料号、类型、规格、宽幅、供应商、单位、状态、期初结存、安全库存**。

- 文本列两种改法：**直接设为该值**（全部统一）或 **只替换部分内容**（如把宽幅 250 换成 260，供应商"松杨"改成"松杨电子"）
- 数字列（期初/安全库存）：**设为该值** 或 **增减**（填 -100 即批量扣减，不会减成负数）
- 批量 **停用 / 启用**：停用的不出现在录单下拉和库存页，数据仍保留
- 批量 **删除**：**有历史单据的自动改为停用**（保证流水可追溯），无单据的才真删

单条编辑：点任意物料进入详情页，A–G 列逐项改。

要找回停用物料：切到「含停用物料」→ 勾选 → 批量启用。

### 物料档案也能从 Excel / CSV 批量导入

「物料」页 → **批量导入** → 选文件 → 预览 → 确认。

- 支持 `.xlsx / .xlsm / .csv`，首行表头，也可先下载模板照着填
- **「物料名称」必填**，其余列可缺；表头认别名（品名/料号/编号/型号/类别/宽幅/预警值…）
- 匹配规则：先按**料号**、再按**名称**匹配已有物料
  - 合并更新（默认）：只补空字段，并用表里的期初/安全库存覆盖
  - 完全覆盖：表里所有非空值都覆盖（含物料名称）
  - 跳过已有：只导新物料
- 导入后会在物料页顶部显示"新增 X 项，更新 Y 项，跳过 Z 项"

> 没有表头也行，按 A=名称 B=料号 C=类型 D=单位 E=期初 读取。

### 单据用 Excel / WPS 表格直接导入

**入库页和录单页都有「⬆ 从 Excel / WPS 导入」按钮**（出库页也有，走 `/out/import`）。

支持 `.xlsx / .xlsm / .xls / .et(WPS) / .csv`，流程是 选文件 → 预览 → 确认导入。

表格怎么填（列顺序随意，缺列没关系，首行表头）：

| 日期 | 物料名称 | 料号 | 类型 | 规格 | 宽幅 | 供应商 | 单位 | 进 | 出 | 备注 |
|---|---|---|---|---|---|---|---|---|---|---|

**数量两种写法，任选其一：**

- **「进」「出」分两列**（推荐）：一行同时有进有出会生成两笔单据
- **「数量」+「进出」两列**：进出列填"进"或"出"；没有进出列时按页面默认类型（入库页=进、出库页=出）

导入时的行为：

- **在入库页导入**只取表里的"进"，出库行自动忽略；**出库页**反之（提示会写明忽略了几笔）
- 物料按 **料号 → 名称** 匹配；**表里没有的新物料会自动建档**，A-G 列信息一并写入
- **出库超库存的行会被跳过**并提示可用量（可勾选"允许超出库存"放行）
- 日期为空的行用页面上填的默认日期；`2026/9/3`、`2026年9月3日`、Excel 日期序列都能识别
- 表头认别名：单据日期/时间、品名/名称、编号/型号、入库数量/出库数量、客户/单号/摘要、类别/幅宽…

> WPS 用户：.et 直接导；老的 .xls 若报错，先另存为 .xlsx；CSV 支持 UTF-8 和 GBK。
> 不确定格式就先点**下载导入模板**照着填。

### 件数换算（数量 / 件数 / 每件）

录单页和导入都支持三个数：**总数量、件数、每件**，填任意两个自动算第三个。

- 数量 200 + 件数 3 → 每件 66.67（不可整除保留两位小数）
- 件数 5 + 每件 20 → 数量 100
- **只填总数量也完全可以**，件数和每件留空不影响记账

### 库存历史（台账）

物料列表、库存列表每行都有 **📈**，点进去看这种物料的全部进出记录，
每行带**当时的结存余额**（期初 + 进 − 出逐笔滚动），可按月份筛选。

### 排序与搜索

- **点表头列名排序**：物料页、库存页、流水页都能点，三态循环 默认 → 升序 ▲ → 降序 ▼
- **模糊搜索**：库存页搜名称/料号/供应商/类型/规格；流水页搜物料/料号/备注/类型。不分大小写

### 导出真正的 Excel

库存、流水、月报都能导出 `.xlsx`（带冻结首行、表头配色），
**导出的是当前筛选和排序后的结果**。月报导出保留原表"物料 × 每日进/出"的版式。

### 入库 / 出库分开录

底部导航 **📥 入库** 和 **📤 出库** 是两个独立页面，界面一样，都含原表 A-G 七列：

**入库页**：只能入，备注默认填"单号/客户"，适合收货时快速登记。
**出库页**：只能出，多一列 **「可用」实时显示当前库存**，数量一超就标红 ✕；
提交时**超出库存的行会被拦下不保存**，并提示"N 行因超出库存未保存：某某(可用多少)"，避免库存变负数。

两页互不干扰，各自有独立的历史流水（入库流水 / 出库流水），
也可去「流水」页看合并的全部单据。原来的通用「/txn」页仍保留，可在一行里选进或出。

### 录入页：照着原 Excel 的格子填

「录单」页就是原表的行样式，一行一笔，表头依次为：

**日期 ｜ 供应商 ｜ 类型 ｜ 规格（米）｜ 宽幅 ｜ 物料名称 ｜ 料号 ｜ 单位（卷）｜ 进/出 ｜ 数量 ｜ 备注**（还可加出 状态 / 期初 / 安全库存 列）

- 物料名称输入时会联想已有物料，**选中即自动带出其余 A-G 信息**
- 也可以整行手填一个**新物料**，保存时自动建档（期初、安全库存可直接在这一行填）
- 行里改了 A-G 任一格，保存时会同步更新该物料档案
- 只有填了**名称或料号**且**数量 > 0** 的行才会保存；日期留空的行默认用第一行日期
- 点 **＋ 再加一行** 可继续加行，一次提交多笔

### 改表头（列映射）

入库页底部 **⚙ 修改表头名称 / 显示 / 映射**，可自定义：

- **显示名**：比如把"类型"改成"类别X"、"物料名称"改成"品名"，入库页表头立刻跟着变
- **列序**：调整列的先后顺序
- **是否显示**：不用的列可关掉（如"状态"），入库页就不出现
- **导入别名**：Excel 导入时，用哪些名字认这一列（自定义的表头名会自动加入别名）

改错了点 **↺ 恢复默认** 即可。别名改完后，你自己的 Excel 表头不用改名也能直接导入。

### 系统自检 🔍

「物料」页 → **🔍 自检**（或访问 `/sys`），可以看到：

- **数据体检**：孤儿单据、缺名称的物料、非法日期/数量、负库存、重名物料，一条条列出来；一键清理
- **库概况**：物料数、单据数、起止日期、文件大小、数据库路径
- **一键备份**：生成 `.bak` 文件（在程序目录，自动保留最近 10 份）
- 启动时也会自动备份一份，并在窗口里提示体检结果

### 数据是怎么保住的（底层）

| 机制 | 作用 |
|---|---|
| 外键约束 | 删除物料不会留下无主单据（老库升级时自动开启） |
| WAL 模式 | 写入时读操作不卡；断电也不易损坏 |
| 事务 | 批量删除 / 批量导入 / 列映射保存，要么全成功要么全回滚 |
| 在线备份 | 用 SQLite 官方 backup API，拷出来的库一定是一致的 |
| 写前校验 | 数量非数字、NaN、负数一律挡下；日期非法自动回退到今天 |

**换手机 / 重装**：把 `warehouse.db` 复制走即可，全部数据就这一个文件。
出问题就把 `.bak` 改名回 `warehouse.db` 还原。

## 三、首次使用三步走

1. **物料 → 逐个点开 → 填「期初结存」**（原表上月结存是坏值，无法继承，需手工录入一次）
2. 顺手填「安全库存（预警值）」，低于它会在首页和库存页标红

## 四、数据结构

- `materials` 物料档案：供应商 / 类型 / 规格 / 宽幅 / 名称 / 料号 / 单位 / 期初 / 安全库存 / 状态（常用·不常用·呆滞）
- `txns` 单据流水：日期 / 物料 / 进或出 / 数量 / 备注（单号、客户）
- `v_stock` 视图：实时库存，由单据聚合得出，不存冗余数

原模板的"呆滞/不常用"标记保留为物料状态字段；原表的"上月结存/本月结存"由 **期初 + 流水** 取代。

# 七、采购台账（v3.0 起）

仓库与采购是两套账，唯一连接点是**到货**：采购到货才生成入库单，下单不会让库存涨。

## 核心口径

| 规则 | 说明 |
|---|---|
| 到货才入库 | 避免"钱付了货没到，账上却有了" |
| 金额现算 | 只存数量+单价，金额/税额/价税合计查询时算，改数量不会挂着旧金额 |
| 双单价 | 订购价与到货实价分开，供应商调价能看出差异 |
| 状态自动推导 | 到货数量变了状态自己跟着变，不会出现"明细齐了单头还写部分到货" |
| 欠款只按到货算 | 没到的货不该先付钱 |

## 四个页面

- **采购台** 🛒：看板（本月采购额/已付/进行中/逾期）+ 按状态、供应商、关键字筛选
- **新建采购单**：多行明细，输入即联想物料，实时算金额税额价税合计
- **采购单详情**：明细、到货登记、付款登记、状态流转
- **供应商**：各家的采购额、已付、欠款

到货支持**部分收、多次收**，超交自动拦截；撤销到货会**连带删除入库单、库存扣回**；
删采购单会连带撤销所有入库单，不留孤儿库存。

## 双单位换算

按采购单位收货、按库存单位入账，单价同步折算：

> 采购 3 卷 × 350 元/卷 → 入库 **300 平米**，成本单价 **3.5 元/平米**
> 金额不变：300 × 3.5 = 3 × 350 = 1050

单位**可随意改**：全局单位字典（卷/平米/米/张/个/kg/箱…）是候选+手输，
输过的新单位自动进候选。换算率只影响之后的到货，已入过库的存量不动。

## 采购导出（v3.6）

采购页可导出四类 Excel，跟随筛选结果：

| 类型 | 内容 |
|---|---|
| 采购单汇总 | 单号/日期/交期/供应商/状态/税率/订购金额/税额/价税合计/已付/欠款 |
| 采购明细 | 含**未到货量**（对账关键字段） |
| 到货流水 | 到货日期/数量/单价/金额 |
| 付款流水 | 付款日期/金额/方式 |

# 八、导入能力（v2.1 ~ v3.5 多轮实测）

## 支持的表格写法

| 写法 | 支持 |
|---|---|
| 一行一笔（进/出分列） | ✅ |
| 一行一笔（数量+进出列） | ✅ |
| 双层表头宽表（一行日期+一行进出） | ✅ 你的原表 |
| 单层表头宽表（`09-01进` 写在一格） | ✅ v3.5 |
| 无表头 | 支持**手动指定列** |
| 多 sheet（第一张是封面） | ✅ 自动跳到有数据的表 |

## 已处理的数据陷阱

- **汇总列**自动跳过，不会把"汇总进"当成某天的单据（曾导致库存翻倍）
- **宽幅小数**正确保留（0.035 不会被截成 0）——宽幅是物料指纹的一部分，
  丢宽幅会把不同宽幅的同名物料合并成一条
- **同名不同规格**按「名称+规格+宽幅」指纹拆分成独立物料
- **「单位（卷）」列里填的是卷数**，真实单位从表头括号里提取
- 数量有上限（1e9），表里多输几个零不会把库存冲爆
- 日期支持 `2026/9/3`、`2026年9月3日`、`2026.9.3`、Excel 日期序列

# 九、数据是怎么保住的（底层）

| 机制 | 作用 |
|---|---|
| 写锁 + BEGIN IMMEDIATE | 多线程排队写，撞锁自动重试，并发不会 500 |
| 事务 | 录单、导入、批量删除要么全成功要么全回滚，不会写一半 |
| 一次性令牌 | 防重复提交（网络卡顿时连点两下不会记两笔） |
| 外键约束 | 删除物料不会留下无主单据 |
| WAL 模式 | 写入时读操作不卡，断电不易损坏 |
| 在线备份 | SQLite 官方 backup API，自动保留最近 10 份 |
| 写前校验 | 数量非数字/NaN/负数/超大值一律挡下，日期非法回退 |
| 公式注入防护 | 导出文本以 `= + - @` 开头自动加单引号 |
| 启动自检 | 数据库损坏会提示有几份备份、怎么还原，而不是一闪而过 |

**换手机 / 重装**：复制 `warehouse.db` 即可，全部数据就这一个文件。
出问题把 `.bak` 改名回 `warehouse.db` 还原。异常详情查 exe 旁边的 `warehouse.log`。

# 十、单价含税开关 + 采购单汇总（v3.7）

## 单价口径：可选含税 / 不含税，默认含税，税率默认 13%

新建采购单时可选「含税单价」或「不含税单价」，**默认含税、税率默认 13%**。

两种填法结果一致，举例（数量 10、税率 13%）：

| 口径 | 单价 | 不含税金额 | 税额 | 价税合计 |
|---|---|---|---|---|
| 含税单价 | 113 | 1000 | 130 | **1130** |
| 不含税单价 | 100 | 1000 | 130 | **1130** |

- 选**含税**：不含税金额 = 数量 × 单价 ÷ (1+税率)
- 选**不含税**：税额 = 数量 × 单价 × 税率

口径记在采购单上（`pos.price_tax`），订购价与到货实价共用同一口径，
全系统金额计算都先过 `net_price()` 折算，不会出现两种算法混着用的情况。

> 升级说明：老采购单按「含税」处理（与升级前逻辑一致，不翻旧账）。
> 若某张老单当时是按不含税填的，进详情页改一次口径即可。

## 采购单汇总：独立保存，便于单独查看

金额的两种做法各有毛病：

- **纯现算**：改了税率或单价，历史单金额也跟着变，跟当时打印给供应商的凭证对不上
- **纯落库**：改了明细忘了更新，就是死数据

现在的做法是**每次变动后重算并落一份快照**到 `po_summary` 表：

建单 / 改明细 / 改单位单价 / 到货 / 撤销到货 / 付款 / 删付款 —— 都会自动重算。

**新增「采购单汇总」页**（采购台有入口，也可直接访问 `/po/summary`）：

- 顶部合计：订购金额、税额、价税合计、已付、欠款、已到货金额
- 每单一行：订购数量、不含税金额、税额、价税合计、已到货、未交、已付、欠款
- 可按状态 / 供应商 / 月份 / 关键字筛选
- 可导出 Excel（17 列，含单价口径与快照时间）

与库存记录**分列**：这页是**采购口径**（订了多少、付了多少、还欠多少），
库存看的是**实收数量**，两者互不干扰。

**欠款为负表示多付**（付了钱但货退回），页面会显示成绿色的「多付」。

> 升级老库：首次打开汇总页会自动把所有采购单补算一次快照。

# 十一、物料页按月 / 按天看状态（v3.8）

## 需求

物料页以前只显示「档案期初」和「实时库存」，看不出**这个月到底走了多少**，
想看当月情况得跑去月报页。

## 现在的口径

| 选择 | 显示 |
|---|---|
| **默认（当月）** | 月初结存 / 当月进 / 当月出 / 月末结存 |
| 选定日期 | 前结存 / 当天进 / 当天出 / 当天结存 |
| 「全部时间」 | 档案期初 / 累计进 / 累计出 / 当前库存 |

**期初不是档案里的 opening**，而是「截至该期间开始时的实际结存」：
`opening + 期间之前的进 − 期间之前的出`。

这样选 10 月看到的期初就是 9 月月末的数，跟月报完全对得上，
不会出现"每个月的期初都等于档案期初"这种对不上账的情况。

实测：9 月月末 402.00 = 10 月月初 402.00 = 全部时间结存 402.00 = 实时库存 402.00。

## 用法

页面顶部两个选择器（选完自动刷新）：

- **按月份看**（`type=month`，默认当月）
- **或按某一天看**（`type=date`，选了日期就以日期为准）

下方三个快捷按钮：**当月 / 全部时间 / ← 回到当月**。

表格底部显示本期合计（进、出）。当天模式下会提示"当天有进出的 N 种"。
表头可排序：期初、进、出、期末都支持点列头排。

> 口径参数会跟着「表格编辑」「含停用物料」等按钮一起传递，切换后不会丢。

# 十二、月报洞察：本月之最 + 环比趋势（v3.9）

月报页新增两块，在原有的「物料 × 每日进/出」明细表**上方**。

## 本月之最（各取前 5，带环比）

| 榜单 | 统计口径 |
|---|---|
| **采购到货最多** | 按 `po_receipts` 到货数量（采购单位） |
| **用得最多（出库）** | 按 `txns` 出库数量 |
| **采购金额最多** | 到货数量 × **到货实价** |

**采购按「到货」统计**，下单不算 —— 与"到货才入库"的口径一致，
否则"订了 1000 但只到了 200"会被误当成采购了 1000。

金额用**到货实价**而非订购价：供应商调价是常态，用实价才对得上实际付的钱。

每条后面跟着与**上月**的环比（↑/↓ + 百分比），上月没数据就不显示箭头，避免误导。

## 每种物料的环比趋势

一行一个物料，三列对比：

| 列 | 内容 |
|---|---|
| 入库 | 本月 vs 上月，↑↓＝ |
| 出库 | 本月 vs 上月，↑↓＝ |
| 采购金额 | 本月 vs 上月，↑↓＝ |

按「本月动静」排序（出库+入库多的在前），没数据的月份显示「－」。

**跨年正确**：查 2026-01 时对比的是 2025-12。

## 一个坑（已处理）

采购明细可能没建档（`material_id` 为空）。如果只用 ID 关联，
"采购的铜箔"和"出入库的铜箔"会**拆成两行**，趋势表出现重复物料。

现在按 ID 优先、为空时用名称反查物料档案，两边归到同一行。实测 3 个物料只有 3 行，无重复。

## 压测揪出的 bug

### 手工设「已完成」但零到货，状态不被纠正

建单时若手工选了「已完成」，程序原样写入，**不会根据到货事实纠正**。
压测中 19 个单子标着「已完成」，实际一件没到 —— 采购台看板、汇总页全部失真。

修复：建单后调用 `refresh_status()` 把状态拉回事实（零到货 → 已下单）。
修复后 19 单 → 0 单。

> `derive_status()` 对「草稿」「已取消」仍不自动改 —— 那是人工终态，不该被覆盖。

# 十四、采购模块重复提交防护补齐（v3.11）

## 问题：采购模块的 5 个写入操作全部没有防重复

v3.3 加一次性令牌时，只覆盖了录单、入库、出库、建单、导入、批量改、表格保存，
**漏了采购详情页的 5 个入口**，而它们的模板都发了令牌、后端却从不核销。

实测后果（订 100 卷）：

| 操作 | 连点两下 | 后果 |
|---|---|---|
| **到货登记** | 每次到 30 | 已收变成 **60**，库存平白多 30 |
| **付款登记** | 每次 1000 | 变成 2 条共 **2000，多付 1000** |
| 加明细 | 加 1 条 | 变 2 条 |
| 改状态 | 幂等 | 无实际危害 |
| 改单位 | 幂等 | 无实际危害 |

**付款翻倍是最危险的** —— 钱付出去了，账上还查不出哪里不对。

作为对比，已做防护的录单页：同一令牌提交两次，第二次被正确挡下。

## 修复

给 5 个路由全部加上 `take_nonce()` 校验，重复时返回友好提示而非写入：
「这一下点重了，没有重复收货，请刷新后重试」。

同时 `po.html` 的 5 个表单从「各发一个令牌」改为**共用一个**，死令牌减少 80%。

## 顺带修掉一个隐蔽的死锁陷阱

令牌池原先用 `set` 存储，满仓时淘汰 `list(set)[:250]`。
**set 的迭代顺序由哈希决定，是随机的** —— 淘汰的并不是"最老的"，
而是随机丢掉一半。用户正在填的表单令牌有 **50% 概率**被误淘汰，
提交时被判成"重复提交"，填了半天的数据静默丢失。

改为 `OrderedDict` + `popitem(last=False)` 先进先出，
淘汰的一定是最老的那批。实测：最早发的令牌被淘汰，最新令牌始终有效。
